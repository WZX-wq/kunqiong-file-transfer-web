# 当前数据库结构说明

核对日期：2026-10-29。以下运行状态由本机 MySQL 8.0.41 实际查询并与关系表读回结果核对；不包含账号明文、文件内容或凭据。

当前数据库共 **26 张物理表**：21 张关系业务/审计表、1 张上传会话表、1 张结构迁移表、1 张关系存储状态表，以及保留的业务快照表和审计源表。业务数据已从快照回填到 20 张受管关系表；审计事件同时保留在旧审计表并镜像到 `kq_audit_log`。

- 关系存储是当前业务权威来源：`kq_relational_store_state` 的 `metadata` 状态记录 revision、迁移来源 revision 和各表计数；当前 20 张受管关系表共 590 行，源快照 revision 为 43，关系 revision 为 8。
- 当前数据核对：用户 3、组织 1、资源 113、文件元数据 221、收集提交 10、分发批次 1、消息 52、订单 15、账号记录 41；完整表计数见关系存储状态行。
- `kunqiong_app_state` 保留原快照作为迁移/恢复来源，不再作为已切换实例的业务读写权威。迁移后持续业务写入由关系存储 revision 管理。
- 审计保留双写兼容：`kunqiong_audit_log` 是既有审计源表，`kq_audit_log` 是关系模型镜像；两表记录数在核对时一致，且会随新请求增长。
- 应用启动时将关系表装配成兼容元数据对象，业务模块暂时继续使用这层对象。持久化按稳定业务键逐实体同步：新增行插入、变化行定向更新、移除行定向删除，未变化行跳过。revision、各表计数和行变更在同一事务提交，失败时全部回滚。
- 正常保存使用与 revision 绑定的进程内关系行缓存，不再对所有受管表执行 `SELECT *`；只有进程首次装载、缓存失效或发现跨进程 revision 冲突时才从数据库重新读取。每次保存仍需遍历兼容对象并映射实体，CPU/内存开销会随对象规模增长；这不是直接 SQL Repository，也没有据此验证多节点水平扩展。
- 未启用关系模式时仍可使用本地文件模式：业务快照在 `storage/metadata.json`；审计在 `storage/audit`。
- 文件正文保存在磁盘；当前支持 `storage/users/<存储所有者目录>/<随机存储名>`，兼容旧 `storage/files` 和 `storage/collections/<task>/<submission>`。MySQL 不保存文件 BLOB。
- MySQL 关系模式下，续传会话清单以加密形式存入 `kq_upload_session`，启动时从 MySQL 恢复；旧 `session.json` 只做幂等迁移输入。文件分片和 `.done` 标记仍在 `storage/tmp`，不是登录会话表，也不是 v4 的服务端业务草稿。
- 前端本地状态 `src/lib/collection-form.js` 使用浏览器 `localStorage` 保存创建草稿和结构复用；它不是服务端 JSON 文件，也不会进入 MySQL。
- `storage/metadata.json`、`storage/audit` 及数据库迁移备份仅在本地模式、首次迁移或恢复时使用；当前关系模式下不作为业务权威源。保留这些副本是为了恢复，不代表在线业务数据没有写入 MySQL。

## 写入验证与容量边界

- `npm run test:db-relational-sync` 使用本地 MySQL 8.0.41 的真实关系表和只回滚事务，覆盖无变化写入、主键保持、插入/更新/删除、收集提交与文件关系、revision 行锁、并发快照合并和事务失败恢复。脚本创建的合成用户均带唯一前缀；测试事务全部回滚，不提交业务 revision。
- `npm run test:db-relational-sync` 在本机 MySQL 8.0.41 上覆盖无变化写入、主键保持、增删、revision 行锁、并发等待和事务回滚。缓存预热后加入 5,000 个带唯一前缀的合成用户；5,590 行无变更同步约 201 ms，改单行约 221 ms。所有合成写入在事务内回滚，未提交 revision。
- `npm run test:db-backup-restore` 在随机命名的隔离临时库中完成关系 schema 初始化、合成用户写入、`mysqldump` 导出、恢复到第二个临时库及应用读取校验。两个临时库和临时导出文件均已删除。该演练验证工具链和关系数据可恢复，不包含生产数据、备份保留策略或真实生产介质故障。
- 该恢复脚本需要本地 MySQL 账号具备创建和删除数据库权限；可通过一次性进程环境变量 `KQ_TEST_DB_ADMIN_USER`、`KQ_TEST_DB_ADMIN_PASSWORD` 提供，应用 `.env` 仍使用受限账号，不要把管理员凭据写入仓库或项目配置。
- 以上是本机受控烟测，不代表生产容量或 SLA；没有执行持续多进程压力、峰值并发、磁盘/连接池耗尽或故障切换。生产上线前仍需按目标数据规模执行持续压测和真实备份介质恢复演练。
- 服务健康检查在 8047 返回 HTTP 200，MySQL 关系模式已启用；关系状态 revision 为 8，源快照 revision 为 43，20 张受管业务表计数与状态行一致。临时启动的新进程也成功从 MySQL 恢复续传会话和磁盘分片，测试后已清理。

## 重要嵌套结构

- `collections[].submissions[]`：`id, participantKey, uploadSessionId?, participantName, submitterUserId, submitterName, fieldValues, materialIds, submittedAt, files[]`。
- 文件对象：`name, relativePath, storedName, storageOwnerId?, size, mimeType, reviewStatus, scanEngine, scannedAt, originalName?, originalRelativePath?, materialId?`；分发文件可加 `distributionRecipientUserId`。
- 材料项：`id, name, required, namingPattern?`；当前不是 v4 全量数量/样例/内容预检模型。
- 自定义字段：`id, label, type, required, help?, options?, showWhen?`；条件引用下拉字段并由服务端验证。
- 组织成员：`id, userId, email, phone, displayName, role, status, invitationId, joinRequestId, joinSource, joinMessage, requestedAt, reviewedAt, joinedAt, invitedAt, invitationExpiresAt`。
- 品牌：`enabled, name, introduction, logo, revision, updatedAt`。Logo 当前可为校验后的 WebP data URL，不是独立文件表。
- 内部标记：`auditStorage` 标识审计存储迁移；`_localRevision` 等用于快照修订与本地镜像。它们不是业务实体。

## 当前边界与后续关系化原因

服务仍在内存中维护完整兼容对象，关系数据库承载持久化数据并执行按实体的事务同步。revision 行锁可以串行化应用写入，但关系模型尚未改造成业务模块直接调用的实体 Repository；关联完整性仍主要由应用校验，不能据此保证多实例压力或复杂查询性能已解决。权限、成员、订单、分发映射的关联也没有全部配置数据库外键。

需要新增名单、逐项审核、个人草稿和事件追踪时，建议逐域迁移为关系表。拟议方案单独放在 02 文件中，不会改变当前程序读写方式。
