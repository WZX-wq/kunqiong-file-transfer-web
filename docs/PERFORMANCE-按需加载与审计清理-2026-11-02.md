# 按需加载与审计定时清理

本轮完成本地代码、隔离数据库和界面回归，未提交、推送或部署，未清理真实业务数据库。与上一轮导航缓存优化共同保留在工作区。

## 请求和数据读取

| 场景 | 当前行为 |
| --- | --- |
| 登录状态 | `/api/auth/me` 支持 `X-Kunqiong-Auth-View: identity/summary/full`；保活只读会话与本人，摘要仅加载必要团队信息；设置和详细资料按需读取；旧客户端不传头时保持完整响应 |
| 导航 | 同会话身份、会员概览、运行配置、套餐价格共用短期缓存和进行中的请求；退出、换号、401及账号变更会清理相应缓存 |
| 记录 | SQL完成所有者、分类、日期、状态、搜索筛选；普通记录每页8条，文件中心每页7条，接口上限50条；获取当前页及跨页总数 |
| 记录变更 | 浏览不再逐条验证远端链接或全量PUT；变更用增量POST；按分类清空使用服务端范围与50条一批事务，保护操作开始后新建的记录 |
| 团队资源 | 每页8条，SQL统计管理者的筛选总数；普通成员先分批验证加密收件人规则，只加载可访问页的文件图；权限过滤后的总数不泄漏隐藏资源 |
| 团队统计 | 卡片统计独立于当前页和搜索结果，翻页后不变成当前页数量 |
| 消息 | 首页只取未读COUNT摘要；打开消息中心取20条，加载更多追加；已读和删除局部更新，不重新拉取整个邮箱 |
| 会员 | 概览只读已保存的权益及最近10笔订单；独立维护任务处理支付对账；支付窗口仍请求权威支付状态，订单中心保留完整订单入口 |

搜索带防抖与取消处理，较旧的响应不能覆盖较新的搜索结果。账号切换会清空已加载的私有页面状态。

团队成员名单目前仍按授权范围加载，用于成员管理和权限展示；大团队及普通成员的加密定向资源检索仍可能需要扫描多批元数据，未宣称所有查询都变成常数时间。

## 前端与传输

- 首页、会员、团队、后台、设置、记录、分发与公开页面使用React.lazy，悬停或聚焦导航时预取对应代码；省流量或2G连接不预取。
- 页面代码加载失败提供重新加载入口；内部视图切换保留应用外壳。
- 统一刷新调度器合并焦点/可见性事件，同键任务不重入；隐藏页面暂停自动请求；支付中的概览15秒刷新，支付窗口状态轮询保留。
- 复用MIT许可的expressjs/compression处理大于1KB的文本响应压缩与Vary协商，跳过下载附件和下载流。

## 审计保留策略

后台系统配置增加访问日志保留天数和清理间隔，账号及安全日志保留项继续可编辑。

| 配置 | 新配置默认值 | 范围 |
| --- | ---: | --- |
| `auditAccessLogRetentionDays` | 7天 | 1–3650天，实际不超过关键日志保留期 |
| `auditLogRetentionDays` | 30天 | 1–3650天 |
| `auditCleanupIntervalMinutes` | 60分钟 | 1–1440分钟 |

已有保存的保留天数继续生效，包括之前保存的90天；新默认值不强制覆盖已有设置。

维护任务每分钟检查是否到期，启动不执行阻塞清理。MySQL每批最多500条，每个类别每轮最多10批；积压在下一分钟继续，不与前台业务响应串行等待。总量仍有5000条保护上限，优先删除最旧访问日志，访问日志不足时再删除最旧关键日志，因此实际保留时长可能短于配置天数。上限裁剪同进程共用单个执行任务。

本地兼容存储使用相同的分类保留规则。业务数据库模式仍使用关系表按需读取，不回退到整库JSON加载。

## 请求指标

`X-Request-Id`关联单次请求。`Server-Timing`包含准备阶段、SQL、连接等待和总耗时；访问审计记录同样的耗时及SQL次数。准备阶段包含其中发生的SQL，指标不能简单相加。指标不记录SQL参数、登录令牌或凭据。

业务响应仍等待业务事务提交；审计异步写入不再阻塞正常响应，关闭服务时会等待审计队列。
