更新日期：2026-10-24

## 本次交付

团队所有者或管理员可以在「团队空间 → 团队品牌」设置对外展示名称、Logo 和简介，预览分享页与收集页的效果，保存启用，或者经过确认恢复平台默认展示。

- 对外展示名称与团队账号名称分开，不会因为修改品牌而改掉组织名称。
- 普通成员没有品牌设置入口，直接访问设置地址也会回到允许访问的团队页面；服务端同时检查权限。
- 关联的团队文件页面、企业专属分享和收集链接使用同一套品牌展示；收集成功与下载页面复用品牌信息。
- 品牌名称、Logo、简介会公开给关联页面的访问者。团队文件仍要求原有成员权限，密码、有效期等访问规则继续生效。
- 更新失败保留已保存配置；编辑冲突提示重新加载；图片处理期间撤销权限、停用账号或变更团队时会重新校验。
- 品牌配置归属团队，负责人交接或服务重启后保留。

## 立即体验

打开：<http://localhost:18048/__branding_demo>

该入口使用临时目录、合成团队和示例文件，不读取项目 `.env`，不连接真实数据库或真实 storage。所有者、管理员、普通成员均由入口切换，不需要填写真实密码。验收站目前已恢复平台默认品牌，方便从头测试。

1. 点击「以团队所有者身份进入」，进入「团队品牌」。
2. 上传正常测试 Logo，填写名称与简介，切换分享页／收集页预览，点击「保存并启用」。
3. 回到入口打开「专属分享页」「专属收集页」，检查三项品牌信息一致；「普通收集页」应保持平台默认。
4. 选择「未登录查看专属收集页」，检查访客能看到品牌。该操作不应赋予团队文件访问权限。
5. 切换普通成员，确认没有品牌设置入口；切换管理员，确认可以编辑。
6. 回到所有者页，先点「恢复默认 → 取消」，确认保留；再确认恢复，刷新公开页面后品牌栏消失。

同一浏览器里的身份切换共用 Cookie。需要同时模拟两个管理员编辑时，请在另一浏览器或隐私窗口打开入口并选择管理员。

## 功能规则

| 项目 | 当前规则 |
| --- | --- |
| 管理权限 | 有效团队所有者或管理员；普通成员、外部账号、停用账号不可修改 |
| 展示名称 | 必填，去除首尾空白，最多 80 字符 |
| 简介 | 可选，最多 160 字符 |
| Logo 类型 | 静态 PNG、JPEG、WebP；不支持 SVG、GIF 或动画图片 |
| 原图大小 | 最大 409600 字节，即 400 KiB；界面提示为 400 KB |
| 图片处理 | 复用现有 Sharp 校验，完整解码，去除元数据，保留比例，输出最大 512 px 的 WebP |
| 移除 Logo | 保存后移除图片，名称和简介仍可以展示 |
| 恢复默认 | 清除对外名称、Logo 和简介并停用品牌，不修改团队名称或文件权限 |
| 编辑冲突 | 携带配置 revision；旧版本提交被拒绝，明确重新加载后才覆盖本地草稿 |

展示链接示例：

- 专属分享：`/e/branding-demo/share/branding-public`
- 专属收集：`/e/branding-demo/collect/branding-task`
- 普通个人收集：`/collect/branding-task`，保持平台默认
- 团队文件：`/share/branding-team`，继续要求团队成员权限

新建资源会绑定创建时的品牌团队，防止人员换团队后错误套用新团队品牌。历史资源没有该关联字段时继续兼容原有企业链接逻辑，本次没有批量迁移或冻结历史资源关联。

## 验收站重启和复测

在项目根目录运行：

```powershell
npx vite build
node scripts/serve-team-branding-demo.mjs
```

默认监听 `127.0.0.1:18048`。端口占用时先关闭自己启动的品牌验收进程；每次重新运行脚本会生成新的临时测试数据。原负责人交接验收站使用 18047，本次保留。

品牌专项测试命令：

```powershell
node scripts/verify-team-branding.mjs

```
