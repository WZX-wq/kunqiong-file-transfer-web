## P1：优先修复

### BND-001：异常批量删除参数会进入“全部删除”分支

- 位置：[server/routes/account.js:274](../server/routes/account.js#L274)，尤其 278、290–295 行。
- 证据：`DELETE /api/account/records`，分别提交 `{"ids":[]}`、`{"ids":null}`、`{"ids":"invalid"}`。均返回 200；两条合成记录变成 0 条，已过期分享也被清理。`[null]`、`[{}]` 则静默成功但没有命中目标。
- 影响：调用方遗漏参数或类型错误会造成本人全部记录丢失，并触发已关闭/过期底层资源及文件清理；不是仅仅删除列表展示项。
- 建议：批量删除必须使用非空字符串 ID 数组，逐项校验并去重；清空全部采用明确独立的操作参数或接口。空数组不能作为清空授权。
- 探针：`DELETE-IDS`。

### BND-002：记录替换接口将错误结构解释成空列表

- 位置：[server/routes/account.js:255](../server/routes/account.js#L255)、[server/lib/metadata-normalizers.js:530](../server/lib/metadata-normalizers.js#L530)。
- 证据：`PUT /api/account/records` 的 `records` 为 `null`、`{}`、`"bad"`、`[null]` 时，均返回 200，现有两条记录被覆盖为 0 条。
- 影响：不合法同步数据造成持久化记录丢失。此处与 BND-001 不同，没有证据表明 PUT 同时清理了底层文件。
- 建议：写入前校验整个数组和每条记录；任意一项非法应拒绝整次替换。明确区分合法空数组与非法输入。
- 探针：`RECORDS-SHAPE`。

### BND-003：下载次数限制可被并发绕过

- 位置：[server/services/shares.js:543](../server/services/shares.js#L543)、[server/services/shares.js:1241](../server/services/shares.js#L1241)。
- 证据：上限为 1，发起 6 个并发公开下载请求，状态为 `[200,200,200,200,200,200]`，最终计数为 6。
- 原因：请求前检查计数，响应完成事件中才增加计数；期间的并发请求都能通过。
- 建议：在开始输出文件前原子占用名额，明确失败/断连释放规则；多进程部署需使用跨进程一致的存储或锁。
- 探针：`SHARE-COUNT`。

### BND-004：非布尔值可清除分享密码、打开清理或通知

- 位置：[server/services/shares.js:1187](../server/services/shares.js#L1187)、[server/lib/metadata-normalizers.js:456](../server/lib/metadata-normalizers.js#L456)。
- 证据：`clearPassword:"false"`、`clearPassword:[]`、`clearPassword:{}` 均实际清除密码。清理开关传 `"false"`、`[]`、`{}` 会变成 true；通知 `email:"false"` 也变成 true。
- 影响：关闭意图被反向执行，可能移除访问保护或启用资源清理。
- 建议：JSON API 仅接受真正的 `true/false`；multipart 如需字符串，应显式解析允许的枚举，拒绝其他类型，禁止 `Boolean(value)` 代替校验。
- 探针：`BOOLEAN`。

### BND-005：请求失败仍留下部分修改

- 位置：[server/services/shares.js:1160](../server/services/shares.js#L1160)、[server/services/collections.js:78](../server/services/collections.js#L78)。
- 证据：分享更新 `{downloadLimit:5,status:"bad"}` 返回 400，内存中下载次数限制仍变成 5。收集更新 `{title:"changed-despite-error",maxFileSizeMb:-1}` 返回 400，标题仍已改变。
- 影响：客户端以为更新失败，服务端对象却发生变化；后续其他请求持久化时可能连同这些改动一起写盘。探针确认的是请求后的内存状态，没有把立即落盘当作已验证结果。
- 建议：先在候选副本上完整校验，再一次性提交修改；失败不得改变原对象或产生通知、文件操作等副作用。
- 探针：`PARTIAL-SHARE`、`PARTIAL-COLLECTION`。

### BND-006：分片总数和零字节文件索引没有完整校验

- 位置：[server/routes/upload.js:137](../server/routes/upload.js#L137)。
- 证据：零字节文件上传空分片时，索引 0、1、9999 都返回 200；4 字节文件声明 `totalChunks=9999` 仍返回 200；索引字段为空字符串也能被当成 0 接受。
- 影响：进度与会话的实际分片规划不一致，可写入额外标记文件。完成阶段有逐片与文件长度检查，不能据此声称已绕过最终完整性校验。
- 建议：服务端根据文件大小和协商分片大小计算唯一总数；强制非空安全整数及索引范围。零字节文件也只允许约定的唯一分片。
- 探针：`CHUNKS`。

### BND-007：收集文件类型校验与最终保存路径不一致

- 位置：[server/routes/collections.js:127](../server/routes/collections.js#L127)、[server/routes/collections.js:140](../server/routes/collections.js#L140)；分片完成路径同类逻辑见 [server/routes/upload.js:251](../server/routes/upload.js#L251)。
- 证据：任务仅允许图片，multipart 文件名为 `safe.png`，传入 `relativePaths=["safe.exe"]`，返回 201，最终路径为 `safe.exe`。
- 影响：验证按原始文件名后缀，保存/打包却采用另一后缀，扩展名策略被绕过。探针只使用合成字节，没有将其描述为真实可执行程序或扫描绕过。
- 建议：先解析唯一规范文件路径，校验文件名与路径末段一致；直接上传、分片创建和完成阶段使用同一校验对象，并保留内容扫描。
- 探针：`MULTIPART-PATH`。

### BND-008：非法文件名和 MIME 在上传后才导致 500

- 位置：[server/routes/upload.js:47](../server/routes/upload.js#L47)、[server/services/shares.js:1068](../server/services/shares.js#L1068)、[server/services/shares.js:594](../server/services/shares.js#L594)。
- 证据：含 NUL 或 274 字符文件名可创建会话并上传分片，发布时 500。`mimeType:"text/plain\r\nX-Test: bad"` 发布返回 201，下载返回 500；含孤立 UTF-16 代理项的文件名同样可发布，下载时 500。
- 影响：用户完成传输后才失败，产生不可用资源、临时目录或重试负担。Node 拒绝非法响应头，未验证存在响应头注入成功。
- 建议：创建会话前校验文件名类型、字符、编码、单段字节长度及平台兼容性；MIME 使用允许的语法/映射，拒绝 CR/LF；存储名与显示名分离。
- 探针：`UPLOAD-PUBLISH`、`UPLOAD-PUBLISH-OPTIONS`。

### BND-009：办公文件预览缺少解析和渲染资源上限

- 位置：[src/components/ui.jsx:290](../src/components/ui.jsx#L290)、[src/components/ui.jsx:362](../src/components/ui.jsx#L362)。
- 证据：浏览器代码读取完整 ArrayBuffer，读取所有工作表并生成 HTML。纯函数探针中，实际仅有 1 个单元格、声明范围 `A1:Z1000` 的工作表生成 26,000 个 `<td>`，HTML 为 604,264 字节。
- 影响：很小的稀疏表格也会放大 DOM；更大的范围、工作表数量或解压内容可能占用大量内存并阻塞页面。没有在真实浏览器中运行破坏性大范围样本，也没有测得浏览器崩溃阈值。
- 建议：限制预览文件大小、解压大小、表数、行列和总单元格数；按当前表/分页惰性渲染，解析放入可取消的 Worker，超限提示下载查看。
- 探针：`OFFICE-BOUNDS`，另有源码验证。

## 需要明确的 6 项契约

这些已有实际观察，但在规则明确前不直接标记为确定的业务缺陷。

| 编号 | 当前行为与证据 | 需确定的规则及建议 |
| --- | --- | --- |
| RULE-001 单人收集大小 | 上限 1 MB，两个各 0.75 MB 的文件能创建收集上传会话；代码逐文件比较，不累计同一提交或同一提交人。`COLLECTION-AGGREGATE`，`server/services/shares.js:756`。 | “单人大小限制”究竟为单文件、单次提交总量还是每人累计？若产品意图为累计，当前实现未满足；确认后统一文案和两种上传入口。 |
| RULE-002 分片大小协商 | 请求 chunkSize=1，服务端调整为 1 MB；创建响应没有返回最终大小，查询响应才返回。`CHUNK-SIZE-CONTRACT`，`server/routes/upload.js:132`。 | 如果允许调整，创建响应必须返回协商值并由客户端采用；也可直接拒绝超范围输入。现有客户端正常范围不一定受影响。 |
| RULE-003 Range 下载计数 | 下载上限 1，第一次 `bytes=0-1` 为 206 并消耗一次，第二次 `bytes=2-3` 为 410。`SHARE-RANGE-COUNT`。 | 次数按 HTTP 请求、一次逻辑下载还是完整文件计数？若需要断点下载，应允许同一下载授权内继续 Range。 |
| RULE-004 验证码持有者 | 验证码存储只绑定目标联系方式和 scene；另一个登录账号持有同一有效验证码可绑定尚未被占用的目标。`CODE-OWNER`，`server/services/account.js:621`。 | 以“持有验证码”证明联系方式控制权，还是额外绑定发起验证码的账号/会话？这不能直接描述为验证码泄漏或无验证码绕过。 |
| RULE-005 上传 TTL 精度 | 恢复和周期 sweep 检查 TTL，requireUploadSessionOwner 不逐请求检查年龄。`TTL` 为源码证据，不是时间推进的动态验证，`server/services/shares.js:62`、`:799`。 | 如要求到时立即失效，入口需检查 createdAt；如接受清理周期宽限，应记录和说明该窗口。 |
| RULE-006 支付外部参数 | 纯函数中非法 expire_at 回退到本地期限，9999 年日期可接受；非法 payType 0/3/"bad" 默认微信，`[2]` 变成 2。`PAYMENT-EXPIRY`、`PAYTYPE`。 | 明确支付方式是否可默认、外部期限是否可信以及最大延长期。不能凭本地替身测试断言真实支付回补或续费已通过。 |

分页 `page=2abc/1.5/-1/1001/NaN` 分别被解析为 2/1/1/1000/1（`PAGE`，`server/routes/workspace.js:168`）。这种容错没有造成已验证越权或无界查询，故不单列严重缺陷；若 API 契约要求严格整数，可一并返回明确 400。

## 覆盖限制与补测事项

“全量”指本轮按当前仓库的路由和原生表单入口建立清单、系统排查边界，不表示穷举无限输入或证明没有其他缺陷。83 个声明不是 83 个端点全部分支均已动态覆盖，242 个探针也不是此前 AUTH/TEAM/PAYMENT 整套验收用例已全部通过。

仍需独立补测：

1. 真实浏览器输入、粘贴、输入法、布局与移动端键盘；文件夹选择的跨浏览器差异。
2. OAuth provider、短信/邮件真实通道、支付创建/回调/并发确认/退款或回补；未发送真实通知或发生真实支付。
3. 真实扫描服务、压缩炸弹/超大办公文档、GB 级上传、磁盘耗尽和断网/断电恢复。
4. 数据库与多进程/多实例部署下的唯一性、并发额度和下载计数原子性。
5. 每个角色的全部权限组合、端点所有错误分支及错误持久化恢复。这次属于边界值排查，不替代完整权限审计。

建议修复顺序：P1 数据与安全状态 → 服务端共享类型/长度/数字/日期/路径校验 → 两种上传入口一致性 → 前端实时提示 → 按缺陷补断言回归，再补上述真实环境验证。对历史数据可保留宽容归一化，但对新写入必须先严格校验，不能让读历史数据的容错函数直接承担写接口校验。
