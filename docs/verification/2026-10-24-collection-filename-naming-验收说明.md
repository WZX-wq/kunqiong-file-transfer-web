# 文件命名规则提交功能验收说明

## 一、验收范围

本次验收验证“按规则生成提交名，同时保留原文件名”的完整链路：

- 创建收集任务时，为材料项设置可选命名格式。
- 提交人上传文件后按材料项生成提交名称。
- 提交页展示生成名称，管理页同时展示生成名称和原文件名。
- ZIP 打包使用生成名称，文件内容保持不变。
- 直接上传、分片上传和断点续传使用同一套材料映射。
- 旧任务和未设置命名格式的任务继续使用原文件名。

支持的占位符只有 `{提交人}`、`{材料项}`、`{原文件名}`。文件名中的路径字符会被清理，原文件扩展名会保留；同目录下生成重名时会自动追加 ` (2)`、` (3)` 等编号。

## 二、验收环境

验收站使用临时目录、合成账号和本机扫描协议模拟器，不读取项目 `.env`、正式数据库或正式文件。扫描模拟器只代表“扫描服务返回通过”，不代表真实杀毒能力。

启动前在项目根目录执行：

```powershell
npx vite build
node scripts/serve-collection-naming-demo.mjs
```

脚本输出后打开：

`http://localhost:18049/__naming_demo`

结束验收时在运行脚本的终端按 `Ctrl+C`。重启脚本会重新生成临时数据，之前的验收提交不会保留。

## 三、主流程验收

测试文件：

`test-kits/collection-filename-naming-2026-10-24/命名规则验收样例.txt`

1. 打开验收站，点击“以合成所有者身份打开提交页”。
2. 确认页面显示任务“文件命名规则验收”，提交人身份为“命名验收提交人”。
3. 选择测试文件 `命名规则验收样例.txt`。该验收任务只有一个材料项，系统会自动绑定材料；若页面显示材料选择框，选择“验收材料”。
4. 确认提交页显示生成名称：`命名验收提交人_验收材料_命名规则验收样例.txt`，并能看到原文件名仍为 `命名规则验收样例.txt`。
5. 点击“提交文件”，等待进度完成并确认页面显示提交成功。
6. 返回验收站入口，点击“打开收集管理页”。
7. 在提交记录中确认文件显示生成名称，并在其下方显示“原文件名：命名规则验收样例.txt”。
8. 点击“下载此提交”或“打包下载全部提交”，打开 ZIP 后确认文件名为 `命名验收提交人_验收材料_命名规则验收样例.txt`，文件内容与测试文件一致。

## 四、边界验收

以下场景已由自动化用例覆盖，人工验收时可重点观察页面提示：

- 创建任务使用未知占位符时，服务端拒绝并提示不支持的占位符。
- 命名格式包含 `/` 等路径字符时，不会生成子目录或路径穿越；扩展名仍沿用原文件扩展名。
- 两个文件生成同名时，第二个文件自动追加编号，不覆盖第一个文件。
- 分片上传中重启服务后，继续提交仍沿用首次创建会话时的材料映射和生成名。
- 未设置命名格式的任务仍按原文件名提交，不能影响历史任务。
