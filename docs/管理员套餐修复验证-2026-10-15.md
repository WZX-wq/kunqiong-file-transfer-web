# 管理员套餐持久化与历史恢复

截图账号最近的管理员操作将套餐设为团队版，但旧测试白名单逻辑已将账号及会话写回基础版。前一轮迁移仅凭已支付订单恢复，未覆盖无订单的后台授权，导致团队容量仍为 0 B。

此外，隔离回归复现两条持续性问题：旧会话和 OAuth 登录资料能覆盖后台设置的套餐或有效期；后台重新授予套餐会继承旧套餐已过期的日期。

## 修复

- 账号记录是套餐与有效期的来源，合并登录资料和旧会话时保留后台或支付流程写入的值，包括长期权益的空到期日。
- 仅在旧测试白名单环境启动时，根据最近一次可信管理员审计恢复被写回基础版的账号。无审计、已撤销、禁用、过期或存在更新的已支付订单时不回放旧授权；同步会话并通过正常存储流程持久化。
- 后台重新授予时清除继承的失效日期，企业永久套餐清除旧到期日；明确提交的其他套餐有效期继续生效。审计增加保存后的有效期。
- 恢复不创建订单、不延长原有效期、不发送开通消息；后续管理员撤销仍然生效。

新增 `scripts/verify-admin-plan-persistence.mjs`，使用真实后台、账户和团队接口及一次性存储副本。先在修复前复现历史恢复、旧会话/重新登录覆盖，再复现后台继承失效日期；修复后专项 28 项全部通过。

完整回归：账户接口 119、账户 UI 62、团队接口 184、团队权限 69、团队 UI 148、支付与后台接口 192、支付与后台 UI 54、专项 28、非功能冒烟 50，共 906 项通过。生产构建、Docker COPY 启动检查及差异空白检查通过。
