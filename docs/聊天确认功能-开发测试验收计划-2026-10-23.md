# 聊天确认功能开发、测试与验收计划

> 目的：把聊天里确认想做的功能整理成可实施、可测试、可验收的计划。先解决真实使用中的收文件、交接、命名、定向发送和误删问题，控制范围，不做重复或复杂装修功能。

## 一、功能范围

共规划 6 个功能模块。**“模板来收文件”与“收集模板、自定义字段”统一为一套收集模板**：模板既保存需要收哪些文件，也保存收集表单字段，不额外开发两套相似的模板。

1. 收集模板、自定义字段与模板收文件
2. 企业管理员／负责人交接
3. 按命名规则提交文件
4. 批量分发文件给指定收件人
5. 回收站与文件恢复
6. 团队品牌展示

本计划是需求方案，不代表功能已经开发或上线。具体排期应在确认开发人员、现有接口复用范围后再定。

## 二、分阶段实施

| 阶段 | 开发内容 | 阶段通过条件 |
| --- | --- | --- |
| 0. 规则确认 | 确认角色与权限、模板字段、命名规则、交接对象、回收期限、分发名单格式和品牌展示位置；先准备验收样例 | 每个功能的操作人、权限、成功结果和异常处理都有明确说明 |
| 1. 收集效率 | 统一收集模板、表单自定义字段、模板创建收集任务、文件命名提示与校验 | 新建任务到提交文件的主流程可完整跑通，旧任务不受模板修改影响 |
| 2. 团队管理 | 管理员交接、团队品牌展示、回收站和恢复 | 交接后权限正确；品牌在目标页面显示；误删文件可在期限内恢复 |
| 3. 定向交付 | 批量上传文件、导入收件人、匹配预览、发布和个人领取 | 错误或歧义映射不能发布，已发布文件只有指定收件人可领取 |
| 4. 联合验收与试点 | 回归现有上传、分享、收集、下载；用内部样例和真实试点流程验收，修复阻断问题 | 所有必验项目通过并记录结果，试点负责人确认后再扩大使用 |

## 三、各功能的开发、测试与验收

### 1. 收集模板、自定义字段与模板收文件

- **开发**：管理员可以建立、复制和编辑收集模板，配置任务说明、截止时间、材料项及必交／选交要求；按需添加文本、下拉、日期等常用字段；用模板创建收集任务并生成提交入口。模板更新不应自动改写已经发布的任务。
- **测试**：覆盖字段新增、修改、删除、必填校验、模板复制、创建任务、部分提交、模板更新后的历史任务、手机端布局和无效输入。
- **验收**：用一个模板创建两项必交、一项选交的收集任务；提交人能打开入口、填写字段并分次上传；管理者能看到字段和缺件状态；修改模板后，已发布任务内容保持不变。

### 2. 企业管理员／负责人交接

- **开发**：由当前有权管理员选择新的团队成员并发起交接；新管理员确认后，团队管理权限和相关任务负责人按确认规则转移，并保留交接记录。仅交接授权，不复制或公开团队文件。
- **测试**：测试无权成员发起、交接给非团队成员、对方拒绝或未确认、交接中断、重复提交、原管理员离职／停用及交接后资源访问。
- **验收**：交接完成后新管理员可执行获授权的管理操作；原管理员失去对应管理权限；普通成员不能发起交接；交接记录能查到发起人、接收人和时间；既有任务和文件归属不丢失。

### 3. 按命名规则提交文件

- **开发**：任务创建者为材料项设置命名示例或规则；提交页展示预期格式，上传时校验文件名，并提示或按规则生成提交显示名。保留原始文件名用于追溯，打包下载时使用确认后的命名规则；文件名需清理路径分隔符和不安全字符。
- **测试**：覆盖规则匹配、不匹配、中文和特殊字符、同名文件、超长文件名、扩展名、重命名后下载、规则修改对已提交文件的影响。
- **验收**：提交人能看懂每项材料的命名要求；符合规则的文件可提交；不符合时有明确提示和修正方式；下载包名称符合任务规则，原始名称仍可追溯，文件不能借名称写入其他目录。

### 4. 批量分发给指定收件人

- **开发**：管理员批量上传文件并导入收件人名单，使用唯一编号匹配文件和收件人；发布前提供逐人预览和问题清单；发布时冻结收件人与文件版本的对应关系；个人领取需验证该收件人的访问资格。
- **测试**：覆盖重名、重复编号、缺失文件、未匹配文件、一人多文件、链接转发、未授权下载、发布失败重试、重复点击、收件人更改及文件替换。
- **验收**：未解决的重复编号、缺件或歧义必须阻止发布；每位收件人只能看到并领取分配给自己的文件；转发普通链接不能转移领取权限；发布后映射固定且有记录；重试不产生重复发布或错误授权。

### 5. 回收站与文件恢复

- **开发**：手动删除先进入回收站，支持查看删除时间、恢复和彻底删除；配置并展示保留期限。到期关闭、手动删除和实际物理清理需区分；恢复文件不自动重新开放原分享链接。上线前确认默认保留期及空间占用规则。
- **测试**：覆盖删除、恢复、彻底删除、过期清理、重复操作、无权恢复、共享文件恢复、空间统计和后台清理失败重试。
- **验收**：有权限的用户可在保留期内恢复文件，恢复后内容可用；无权用户不能查看或恢复；彻底删除后不可恢复；恢复不会擅自重新开放已关闭的分享链接；页面清楚说明保留期限。

### 6. 团队品牌展示

- **开发**：团队管理员设置团队名称、Logo 和简短介绍，在分享页和收集页展示；未配置时使用默认样式。首期不做自定义域名和完整主题编辑器。图片限制类型与大小，后端检查上传权限。
- **测试**：覆盖设置、修改、清除、默认展示、错误格式、超限图片、长名称、特殊字符、手机显示、未登录访问和跨团队越权。
- **验收**：授权管理员可以保存和恢复默认品牌；分享页、收集页及手机端显示一致且不破版；普通成员不能修改，其他团队不能读取或覆盖配置；上传失败时保留当前已保存品牌。

## 四、测试与验收方式

1. **开发自测**：分别检查表单校验、命名规则、权限判定、文件状态和异常提示。
2. **接口与数据测试**：检查未授权访问、跨团队隔离、重复请求幂等、并发修改、文件版本和交接事务。
3. **端到端测试**：至少完整跑通“用模板创建收集任务 → 按规则提交文件 → 管理员交接 → 品牌展示 → 文件进入回收站并恢复”以及“批量导入 → 预览匹配 → 定向发布 → 指定收件人领取”。
4. **兼容与回归**：桌面和手机浏览器检查主要页面；确认现有上传、分享、收集、下载、账号和团队功能没有回退。
5. **验收记录**：每条用例记录测试账号角色、前置数据、操作步骤、预期结果、实际结果、问题编号和结论；阻断主流程、越权访问或错发文件的问题修复后再验收。

## 五、上线前必须确认的事项

- 团队管理员、任务负责人和普通成员各自可以做哪些操作。
- 管理员交接是否需要接收方确认，交接后旧管理员保留哪些权限。
- 命名规则是提示还是强制校验，以及最终文件名格式。
- 回收站保留多少天、文件何时彻底清理、保留期间如何计算容量。
- 批量分发采用什么唯一人员编号，收件人用账号还是已验证联系方式确认身份。
- 品牌展示出现在哪些页面，Logo 的格式和大小限制。

这些规则应在开发前由产品负责人确认；未确认的部分先按最小范围实现并标记待定，不把猜测写成上线承诺。
