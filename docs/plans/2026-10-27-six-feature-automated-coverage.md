# 六项新增功能自动化覆盖补齐计划

**目标：** 将六项新增功能的 35 条验收用例逐条对应到隔离自动化断言，确保可覆盖部分补齐、失败行为修复，并在最终复跑中得到全部通过。

**方案：** 复用仓库现有 Node HTTP fixture 与 JSDOM React 测试风格；后端测试只写临时存储，UI 测试模拟接口响应。创建覆盖矩阵，标出每条用例的证据；对照当前页面行为与用例规格，先解决预期冲突再新增断言。真实浏览器视口、持久化状态及文件内容必须有可观察断言；不使用真实用户数据。

**技术栈：** Node.js、现有 npm test 脚本、Vite build、JSDOM、现有测试 fixture。

---

### 执行步骤

1. 盘点所有 35 条用例、当前源码和现有测试；记录 API/UI/文件/边界覆盖，不根据脚本退出码推断覆盖。
2. 对照用例预期与当前产品输出，解决数据导出格式、个收集回收站支持和其他口径差异；必要时先更新用例规格或实现。
3. 为收集字段增加类型校验、条件显示/隐藏、字段数量上限、材料数量上限、提交后管理端导出验证。
4. 为命名、定向发布增加未配置原名下载、入口位置、批量粘贴、空行/缺件、重复提交和发布后映射冻结的断言。
5. 为个人/团队回收站增加个人收集任务恢复、七天到期实际清理和删除文件/元数据验证。
6. 为品牌增加精确大小边界；对窄屏使用真实浏览器或能计算布局的浏览器引擎验证，不把 JSDOM 冒充视口验收。
7. 编写一个隔离跨功能端到端测试，顺序执行收集、命名、交接、定向发布、回收站和品牌验证。
8. 逐条复跑所有相关模块和构建；更新覆盖报告及日志。仅在 35 条均有通过断言、没有待补项时报告“全部覆盖并通过”。
