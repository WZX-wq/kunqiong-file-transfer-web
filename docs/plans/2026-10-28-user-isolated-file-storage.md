# 用户文件隔离存储实施计划

**目标：** 将分享、团队资源和收集提交文件统一存放到上传者专属目录，物理文件名使用原文件名哈希、随机码和原扩展名，并在启动时幂等迁移旧文件。

**架构：** 新增服务端文件存储工具，集中负责安全目录键、文件名生成、路径解析、删除和迁移。资源元数据记录存储所有者与物理文件名；所有下载、预览、扫描、回收站和清理操作都通过同一解析器访问文件。匿名上传使用已签名的访客/参与者标识作为隔离主体。

**技术栈：** Node.js 内置 `node:fs`、`node:path`、`node:crypto`，沿用现有 Express、元数据快照和测试脚本。

---

### 阶段 1：实现统一路径与文件名工具

- 新增 `server/lib/file-storage.js`，提供安全的用户目录映射、`SHA256(文件名)-UUID.后缀` 生成、文件路径解析、文件存在性检查和按资源删除文件。
- 在配置中增加用户文件根目录，并保持旧 `files/`、`collections/` 目录仅用于兼容读取和迁移。
- 验证：单元测试覆盖路径穿越、空身份、中文名/多后缀、扩展名长度、同名文件随机码唯一。

### 阶段 2：切换新上传路径和读取路径

- 分享、团队上传、个人收集和访客收集全部写入上传者目录；记录 `storageOwnerId`，公开接口不得泄露物理目录或内部文件名。
- 更新下载、预览、压缩包、扫描和回收站操作，先解析新用户目录；无新存储元数据的记录继续读取原资源目录。
- 删除资源时仅删除该资源引用的文件，不递归删除用户目录中的其他资源。
- 验证：上传后检查目录/命名；同用户多个资源与不同用户同名文件互不覆盖；下载、预览、团队成员访问和回收站恢复保持可用。

### 阶段 3：幂等迁移旧存储

- 遍历旧分享、团队资源、收集提交和匿名提交目录，按原上传者/提交者归属迁移到用户目录。
- 迁移记录先写入元数据并持久化，再移动文件；重启时可从迁移标记继续，目标存在时校验内容，绝不覆盖不同内容。
- 迁移成功后清除临时标记并删除空的旧资源目录；旧文件缺失或无法安全判断归属时保留原文件并记录可诊断结果，不静默丢弃。
- 验证：中断后重跑、目标同名冲突、缺失旧文件、个人/团队/收集/访客归属，以及迁移前后的内容哈希一致。

### 阶段 4：回归与验收

- 更新上传发布、收集、分发和回收站测试夹具以使用统一路径解析器。
- 运行存储工具测试、上传发布测试、收集测试、定向分发测试、回收站测试、安全测试和构建。
- 最后在隔离副本上执行真实旧数据迁移演练，核对迁移数量、失败数、内容哈希和下载结果。
