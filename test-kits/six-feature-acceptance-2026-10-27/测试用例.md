## 快速开始

- 主应用测试入口：先确认 `http://localhost:8045` 可打开；如本地服务未运行，在项目根目录执行 `npm run dev`。该命令启动本地开发服务，不部署项目。
- 收集字段与材料：打开 `http://localhost:8045/workspace?view=collect`，新建一次性收集任务。
- 命名规则：先执行 `npx vite build`，再运行 `node scripts/serve-collection-naming-demo.mjs`，打开 `http://localhost:18049/__naming_demo`。
- 负责人交接：先执行 `npx vite build`，再运行 `node scripts/serve-team-handover-demo.mjs`，打开 `http://localhost:18047/__handover_demo`，只使用入口提供的合成身份。
- 团队品牌：先执行 `npx vite build`，再运行 `node scripts/serve-team-branding-demo.mjs`，打开 `http://localhost:18048/__branding_demo`，只使用入口提供的合成身份。
- 批量定向发布：打开主应用首页，在文件上传区域右上角点击“批量定向发布”；不要从顶部导航寻找入口。
- 回收站：从主应用进入“回收站”，分别检查个人回收站和团队回收站；永久删除只对本套件创建的测试资源执行。
- 运行完整自动化回归：`npm run test:six-features`。该命令顺序运行收集、交接、定向发布、回收站、团队回收站、品牌、跨功能 E2E 和生产构建。
- 收集管理页当前导出格式为 XLSX；表格将手机号和日期按文本保存，并按内容调整列宽。COL-002 的自动化会解析实际下载的工作簿。
- 每条用例按 P0、P1 顺序执行，将状态填写为“通过 / 不通过 / 阻塞”，并记录实际结果、截图或录屏路径、缺陷编号和执行时间。缺少专用账号或隔离环境时先标记阻塞，不要使用真实客户信息。

- R-TRASH-T：团队文件可进入团队回收站并保留7天；期间占用团队容量且分享关闭；上传者或管理者按权限恢复，只有团队管理者可彻底删除/清空。；来源：src/pages/team.jsx；src/pages/records.jsx；server/services/trash.js；server/routes/workspace.js
- R-BRAND：团队所有者或管理员可保存/修改/恢复默认对外品牌；团队分享及专属收集页展示一致，不扩大文件权限；普通成员不能编辑。；来源：docs/阶段二-团队品牌展示-验收说明.md
- R-BRAND-LOGO：Logo 支持静态 PNG/JPEG/WebP，原图最大409600字节；拒绝超限、SVG和损坏图片，失败不得覆盖已保存品牌。；来源：docs/阶段二-团队品牌展示-验收说明.md；test-kits/team-branding-2026-10-24/测试用例.md
