# 批量分发测试文件

## 规则（2026-10-26 交互改版后）

- **文件名保持原样即可**，不需要加编号、不需要改名。
- 上传文件后，**在每个文件后面直接填收件人**：用户名、邮箱、手机号或账号 ID，收件人必须是已注册账号。
- 行尾实时显示匹配结果：绿色“昵称”= 已匹配，红色“未找到”= 账号不存在，空白 = 待填写。
- 文件多时点右上角“批量填入”，把一份名单按顺序填进各行，再逐行微调。
- 兼容旧格式：文件名带 `001__` 前缀时展示名会自动去掉前缀；名单粘贴成 `001,alice` 两列也能识别。

## 正常用例

1. 选择 `files/001__alice.txt` 和 `files/002__bob.txt`（文件名带不带编号都行）。
2. 第 1 行收件人填 `alice`，第 2 行填 `bob`。
3. 预期：两行分别显示绿色“alice / bob”，“确认发布”可点击。
4. 发布后：管理员看到两个文件；alice 只能看到并下载 `alice.txt`，bob 只能看到并下载 `bob.txt`（发布时自动去掉 `001__` 前缀）。

## 异常用例

- **收件人不存在**：某行填一个未注册账号 → 该行红色“未找到”，下方列出“收件人 xxx 不存在或未绑定账号”，“确认发布”不可用。
- **漏填收件人**：只填了一部分 → 未填的行显示“待填写”，“确认发布”不可用。
- **未授权访问**：把分享链接发给未授权账号，访问必须返回无权提示，不能看到文件列表。

## 历史说明

`roster-valid.csv`、`roster-duplicate.csv`、`roster-missing.csv` 是编号配对时代的用例。改版后不再有“名单编号必须和文件名编号对上”的约束，编号只用于自动去掉展示前缀；配对结果以每行填写的收件人为准。
