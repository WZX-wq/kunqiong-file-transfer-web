## dev(4173) 上传 403「请求来源不受信任」根因修复
- 现象：4173 vite dev 页面上传挂 0%，错误「请求来源不受信任」；但 GET（/api/guest/quota）正常。
- 根因链：vite proxy `'/api': 'http://localhost:8045'` 转发时改写 Host（实测 Host 非 4173）→ 8045 防 CSRF 中间件（f689cd6 引入）比对 `Origin !== getRequestOrigin(req)`（XFH||Host）→ Origin=4173 ≠ Host=8045 → 所有 mutation POST 403；GET 无 Origin 头被 `if (!origin) return next()` 放行。
- 判定实验：直发 8045 且 Host=4173+Origin=4173 → 201（校验逻辑本身对 dev 通过）；经 4173 proxy 同样 POST → 403。
- 修复：中间件对 `/^https?:\/\/(localhost|127.0.0.1|\[::1\]):4173$/` 放行，与 enforceDownloadOrigin 的本机 dev 白名单同口径；沙箱验证 dev 放行/evil.com 仍 403/同源与无 Origin 行为不变。生产不受影响（浏览器无法伪造该 Origin；脚本可无 Origin 绕过，该校验本就只防浏览器跨站）。
- 经验：本机调上传优先用 8045 同源；4173 仅前端开发用。**发现「GET 正常、POST 全挂」先查 Origin 校验**。

## 上传面板长文件名溢出修复（纯 CSS）
- 现象：超长中文文件名把上传面板撑宽、页面横向溢出（用户截图）。
- 根因：`.upload-panel` 是 grid(place-items:center)，**隐式 auto 列会被 nowrap 长内容的 max-content 撑大**，突破 transfer-column 约束——不是 ellipsis 缺失（white-space:nowrap+text-overflow 本来就在，但容器没约束时永远不截断）。
- 修复（styles.css 设计增强层第 9 块）：`.upload-panel { grid-template-columns: minmax(0, 1fr); }` + `.file-queue/.share-result/.file-row/.share-link { min-width:0 }` + `.share-link > span { overflow-wrap:anywhere }`。
- 验证（CDP，DataTransfer + `new File()` 注入超长名文件触发 React onChange——**绕开 Windows 260 字符路径限制**，`DOM.setFileInputFiles` 在 React 异步渲染后 nodeId 过期不可用）：
  - `_verify_panel_overflow_e2e.mjs` 7/7：无横向溢出（scrollW=vw）、面板=列宽、行内约束生效、nameTruncated=true；反向对照还原修复规则 widestRow=1389/nameTruncated=false 证明修复有效。
  - 反向对照踩坑：disable 规则后 re-navigate 会被还原；须在同页注入 `!important` 覆盖 CSS。
- 仅改 CSS，dist 已重建，**刷新页面即生效，无需重启 8045**。
- 布局断言经验：`document.scrollingElement.scrollWidth > innerWidth` 判页面溢出；`getBoundingClientRect().width` 逐级比对列/面板/行宽。
