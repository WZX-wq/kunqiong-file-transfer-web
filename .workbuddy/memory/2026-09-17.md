就下了「代码正确、是浏览器缓存」的结论。**这个断言只能证明 DOM 结构对，证明不了视觉并排。**
用户第三次反馈后，我改用真实浏览器测量，立刻复现了问题。

### 真正的根因（两个缺陷叠加）
用 Chrome headless + CDP 实测（`_layout_cells.mjs`），拿到决定性证据：

```
1440px 视口：
  lower-row  cols=712.609px 445.391px     ← 两栏网格确实生效
  team-card  rect{w:1180}  gridArea=1 / -1  ← 但它横跨了整行！
  status     rect{w:713,y:1230}  gridArea=auto
  同一行=false  team在上=true
```

**缺陷 1（主因）：`.workspace-team-card { grid-column: 1 / -1 }`**
这行是上一轮为「让团队卡通栏」加的。加了 `.workspace-lower-row` 之后，
团队卡变成了 2 列网格的子元素 —— 此时 `1 / -1` 的含义变成「横跨两栏」，
于是团队卡独占整行，把状态卡挤到第二行（y=876 → 1230）。
> 教训：`grid-column: 1 / -1` 是「相对于所在网格」的，换父容器后语义会变。

**缺陷 2：`.workspace-grid > .public-card` 用了「直接子元素」选择器**
两卡降了一层放进 lower-row 后匹配不到，回落到 `.public-card { width: min(570px, 100%) }`
被硬顶成 570px，导致卡片比自己的栅格轨道窄、右侧留白。
（修复后实测 team 从 570 → 713，status 445，两卡宽度和+gap 恰好等于行宽 1180。）

**缺陷 3（修复缺陷 1 后我自己引入的回归）：900px 断点被覆盖**
显式写了 `team{grid-column:1/2}`、`status{grid-column:2/3}` 后，
这两条会盖过 900px 媒体查询里的单列定义，窄屏下状态卡被压成 207px 窄条而不是换行。
→ 子元素有显式 grid-column 时，**响应式断点里必须显式复位**。
